Tolong perbaiki fitur Super Admin > Kelola Akun pada halaman pengaturan akun Divisi.

KONDISI SAAT INI:
- Ada daftar Divisi 1 sampai Divisi 20.
- Setiap divisi memiliki:
  - nama divisi
  - password
  - periode
  - tombol Reset
- Saat ini tombol masih selalu bertuliskan "Reset".
- Saya sudah mencoba mengganti password, tetapi ketika mencoba login menggunakan password baru ternyata password lama masih yang berlaku / password baru tidak benar-benar tersimpan.
- Jadi jangan hanya memperbaiki UI. Perbaiki seluruh alur database, API/server action, autentikasi, dan UI agar benar-benar berfungsi.

==================================================
1. PERUBAHAN TOMBOL PASSWORD
==================================================

Untuk setiap divisi:

KONDISI BELUM PERNAH DI-SETTING:
- Input password kosong.
- Status menampilkan "Belum ada password".
- Tombol harus bertuliskan "Simpan".
- Tombol "Simpan" hanya aktif jika password valid.
- Password minimal 4 karakter sesuai aturan aplikasi.

SETELAH PASSWORD BERHASIL DISIMPAN:
- Status berubah menjadi misalnya "Password sudah diatur".
- Tombol berubah dari "Simpan" menjadi "Ubah".
- Jangan tampilkan password asli yang tersimpan di database.
- Input password setelah tersimpan sebaiknya kosong dengan placeholder seperti "Masukkan password baru".
- Tombol "Ubah" digunakan untuk mengganti password.

KETIKA MENEKAN "UBAH":
- User memasukkan password baru.
- Klik "Ubah".
- Password benar-benar diperbarui di sistem autentikasi.
- Setelah berhasil, tampilkan notifikasi berhasil.
- Status tetap "Password sudah diatur".
- Jangan kembali menjadi "Belum ada password".

Jika proses gagal:
- Jangan mengubah status UI seolah-olah berhasil.
- Tampilkan pesan error yang jelas.
- Data lama tetap dipertahankan.

==================================================
2. PASSWORD HARUS BENAR-BENAR TERSIMPAN
==================================================

INI SANGAT PENTING.

Jangan hanya menyimpan password ke state React/local state/browser/localStorage.

Password harus benar-benar mengubah credential akun yang digunakan untuk login.

Periksa implementasi authentication yang sekarang digunakan aplikasi.

Pastikan:
- akun Divisi 1 menggunakan email/akun yang benar
- akun Divisi 2 menggunakan email/akun yang benar
- dst sampai Divisi 20
- password yang diubah melalui Super Admin adalah password akun tersebut
- setelah halaman direfresh, status password tetap benar
- setelah logout dan login kembali, password baru benar-benar bisa digunakan
- password lama tidak lagi bisa digunakan setelah password berhasil diubah

Jika aplikasi menggunakan Supabase Auth:
- gunakan mekanisme Supabase Auth yang benar untuk membuat/mengubah password.
- Jangan menyimpan password plaintext ke tabel database.
- Jangan membuat kolom password plaintext hanya agar UI terlihat tersimpan.
- Jangan mengekspos service role key ke browser/client.
- Operasi yang membutuhkan service role harus dilakukan di server-side yang aman.
- Pastikan update password dilakukan terhadap user Auth yang tepat berdasarkan user ID/email akun divisi.

Periksa juga apakah selama ini sistem hanya menyimpan "status password" di tabel database tetapi tidak benar-benar mengubah password Supabase Auth. Jika iya, perbaiki.

==================================================
3. JANGAN SALAH USER ACCOUNT
==================================================

Pastikan mapping:

Divisi 1 -> akun Divisi 1
Divisi 2 -> akun Divisi 2
Divisi 3 -> akun Divisi 3
...
Divisi 20 -> akun Divisi 20

Jangan sampai ketika Super Admin mengubah password Divisi 1, yang berubah justru akun Super Admin atau akun divisi lain.

Sebelum melakukan update:
- ambil ID user Auth yang benar untuk divisi tersebut
- lakukan update password berdasarkan user ID tersebut
- verifikasi hasil update

Karena setiap divisi menggunakan satu akun/email untuk login dan password masing-masing diatur oleh Super Admin.

==================================================

Dropdown periode pada setiap divisi juga harus benar-benar tersimpan.

2027/2028

- membuka halaman Kelola Akun lagi

periode harus tetap 2027/2028.

Jangan hanya mengubah state frontend.

Pastikan periode disimpan pada tabel/database yang memang menjadi sumber data aplikasi.

==================================================

atau

Saat halaman pertama kali dibuka:

- tampilkan tombol yang sesuai.

Contoh:

belum ada konfigurasi:

sudah dikonfigurasi:
[ Password Baru ] [ Periode ] [ Ubah ]

Jika halaman direfresh, kondisi tombol harus tetap benar.

==================================================
6. SIMPAN PASSWORD DAN PERIODE SECARA KONSISTEN
==================================================

Saat Super Admin menyimpan/mengubah pengaturan:

1. Validasi input.
2. Pastikan divisi valid.
3. Pastikan user Auth divisi ditemukan.
4. Update password Auth jika password baru diberikan.
5. Update periode/configuration database.
6. Pastikan operasi berhasil.
7. Refresh/fetch ulang data.
8. Tampilkan status terbaru dari database.

Jika salah satu operasi gagal:
- jangan memberikan notifikasi sukses palsu
- tampilkan error
- jangan membuat UI terlihat sudah tersimpan padahal database gagal.

Jika memungkinkan, buat mekanisme server-side yang aman agar perubahan konfigurasi tidak menghasilkan kondisi setengah tersimpan.
